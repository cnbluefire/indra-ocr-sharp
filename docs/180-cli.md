# 180 — CLI (the serial command line)

**Status:** done.

## Goal

Port `indra_ocr/cli.py`: the command line's whole surface, aligned 1:1 with the reference —
the arguments (an argparse port, since the usage line, the abbreviations, the error wording and
the exit codes are all output), the model-folder policy (`models.model_dir`), the page output
(markdown / text / JSON lines, `--out` files) and the exit codes. The worker-process pool
(`parallel.convert_many`) is step `190`; this step runs every input in-process.

## Shape

```
main(argv):
  try: return _main(argv)
  except SystemExit as e:            # argparse: help/version -> stdout, error -> stderr
      write(e.text); return e.code
  except ModelError as e:            # cli.main's own catch
      stderr("indra-ocr: {e}"); return 1

_main(argv):
  a = parser.parse_args(argv)
  if a.out: Path(a.out).mkdir(parents=True, exist_ok=True)
  ext = {"md": ".md", "text": ".txt", "json": ".jsonl"}[a.format]
  failed = 0
  for path, result in convert_many(a.inputs, cores=a.cores, max_pages=a.max_pages,
                                   password=a.password, dpi=a.dpi, mode=a.mode,
                                   pdf_order=not a.model_order, image_ocr=not a.no_image_ocr,
                                   math=a.math, furniture=a.keep_furniture):
      chunks = []
      if isinstance(result, InputError): stderr(f"indra-ocr: {result}"); failed += 1; continue
      for i, page in result:
          if page.source == "error": stderr(f"indra-ocr: {path} page {i+1}: {page.note}")
          chunks.append(json.dumps({...}, ensure_ascii=False) if json
                        else page.markdown if a.format == "md" and page.markdown is not None
                        else page.text)
          if a.timings: stderr(f"{path} page {i+1}: {page.source}, {t.get('total_ms', 0):.0f} ms {page.note}")
      body = ("\n" if json else "\n\n").join(chunks) + "\n"
      if a.out: write (a.out / unique(path.stem) + ext)  else: stdout(body)
  if failed: stderr(f"indra-ocr: {failed} of {len(a.inputs)} inputs failed")
  return 1 if failed else 0
```

## Port notes

- **argparse is ported, not imitated.** The usage line's wrapping (width `COLUMNS - 2`, the
  continuation indent, `_action_max_length` capping at 24, `_format_action_invocation` spelling
  `--cores, --threads CORES` the 3.14 way), `_parse_optional`'s exact/`=`/abbreviation order, the
  `-`/`O`/`A` pattern loop with `_match_arguments_partial` for the `nargs='+'` positional, the
  `--` separator, `dest` derivation, `store_true`'s `False` default, `SUPPRESS` for
  `--help`/`--version`, and `error()`'s `usage:` + `prog: error: …` + exit 2. `_VersionAction`'s
  own help string ("show program's version number and exit") is added when the caller omits it,
  as argparse does. What the CLI never uses (subparsers, mutually exclusive groups, other `nargs`,
  `fromfile_prefix_chars`, deprecated arguments) is not ported.
- **The model folder is chosen here, the download is Core's.** `ModelFolder.Resolve` is
  `models.model_dir`: `--model-dir`, else `INDRA_OCR_MODEL_DIR` (both `expanduser`'d), else the
  Hub cache; the missing-file check is the reference's own `FILES[:2] + FILES[3:]` — `det.onnx`,
  `rec.onnx`, `meta.json`, and *not* `order.onnx`. `ModelDownload.Download` (step `170`) is called
  with the folder only. A `ModelError` reaches `main` and becomes one stderr line and exit 1.
- **The cache is the Hub's own, so the reference's download is reused.** The folder is
  `<HF_HUB_CACHE>/models--datalab-to--indra-ocr/snapshots/<rev-or-sha>`, where the sha comes from
  the Hub cache's own `refs/v3.1.1` file when it exists (`huggingface_hub` writes it). A model set
  the Python tool already downloaded is therefore found and used as it is, and the daily-check
  stamp is the same `.indra_ocr_checked--datalab-to--indra-ocr--v3.1.1` file, so neither tool
  re-checks the Hub for the other. `HUGGINGFACE_HUB_CACHE`/`HF_HUB_CACHE`/`HF_HOME`/
  `XDG_CACHE_HOME` are read in `huggingface_hub.constants`' order.
- **The output is the reference's bytes.** `json.dumps(..., ensure_ascii=False)` with Python's
  separators and float spelling (`PyJson`, `PyFloat`), the `timings` dict in the order the
  pipeline filled it, `dataclasses.asdict(Line)` → `{"box", "text", "conf"}`, the layout blocks'
  `{"label", "bbox", "text"}`, `page.markdown if not None else page.text` for `md`,
  `"\n\n"`/`"\n"` separators, the `--out` `_2`/`_3` de-duplication and `--timings`' trailing space
  before an empty note.
- **`convert_many`'s shape is in `Cli.cs`**: `Plan` (`parallel._plan`: a missing file, a PDF
  that cannot be opened, one unit per page with `min(n, max_pages)`, one unit per image file) and
  the per-input read. The `threads` the model sessions get is `max(1, cores or usable_cores())`.
  The pool itself — the worker processes and their protocol — is step `190`
  (`docs/190-parallel.md`); `Cli.ConvertMany` decides between `Serial` and `Pooled`.
- **`ImageConverter.ConvertFrames` slices like Python.** `read_images(path)[:max_pages or None]`:
  `0` is all frames, a positive value the first ones, a negative value all but the last ones.
  (The PDF side is `range(min(n, max_pages))`, so a negative `--max-pages` renders no page at
  all — both were checked against the reference.)

## Deviations

- **The streams are UTF-8.** Python's redirected stdout/stderr use the locale encoding (GBK on
  this host) and raise on characters it cannot map; the port always writes UTF-8, and asks a real
  console for its UTF-8 code page so the text renders as written. The harness sets
  `PYTHONIOENCODING=utf-8` for the reference. Newlines are still Python's: `\n` becomes
  `os.linesep`, so redirected output and `--out` files hold CRLF on Windows (`PyText.Translate`).
- **Exit codes are the console script's.** `[project.scripts] indra-ocr = "indra_ocr.cli:main"`
  runs `sys.exit(main())`, but `python -m indra_ocr` (`__main__.py`) calls `main()` and drops the
  return value, so it always exits 0. The parity target — and what the port reproduces — is the
  console script (and `uv run indra-ocr`).
- **An unexpected exception prints one line.** The reference lets anything but a `ModelError` out
  as a traceback (exit 1); the port prints `indra-ocr: {ExceptionType}: {message}` and exits 1.
  `--math` with the math models present lands here for now (the `FileNotFoundException` of step
  `200`'s not-yet-ported `MathReader`); without them the model-folder check raises the
  reference's `ModelError` first, which is what the harness checks.
- **`usable_cores()` is `Environment.ProcessorCount`.** Windows Python's `os.cpu_count()` is not
  affinity-aware (it reports the machine's cores) while .NET's count is the process's available
  CPUs; the help text's "(here N)" is therefore machine-dependent in the same way, but computed
  from the process. On this host both are 8.
