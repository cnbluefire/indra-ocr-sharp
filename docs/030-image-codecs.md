# 030 — Gray image types + host image codecs

**Status:** done.

## Goal

Reproduce `cv2.imread(..., IMREAD_GRAYSCALE)` / `cv2.imreadmulti` bit-exactly, using a
managed codec, and define the grayscale contract `Core` consumes.

## Finding: OpenCV 5.0.0 has *three* grayscale formulas

`cv2.imread(path, IMREAD_GRAYSCALE)` does **not** call `cv2.cvtColor`; the colour conversion
happens inside the codec. Measured on the reference machine (cv2 5.0.0), each formula matched
**0 mismatches over 1,000,000 random RGB triples**:

| Source | Formula (`>> 15`, coeffs sum to 2^15) | Rounding |
|---|---|---|
| PNG | `R*9797 + G*19234 + B*3737` | **truncate** |
| BMP, TIFF | `R*9798 + G*19234 + B*3736` | round (`+2^14`) |
| `cvtColor(BGR2GRAY)` | `B*3735 + G*19235 + R*9798` | round (`+2^14`) |

Where they come from:

- **PNG** — libpng `png_set_rgb_to_gray` (OpenCV passes `0.299, 0.587`). libpng recomputes the
  blue coefficient as `32768 - red - green`, giving `9797 / 19234 / 3737`, and the
  non-gamma branch does a plain `>> 15` with no rounding.
- **BMP / TIFF** — OpenCV's own decoders; coefficients `9798 / 19234 / 3736`, rounded.
- **`cvtColor`** — `RGB2Gray<uchar>` from `modules/imgproc/src/color.simd_helpers.hpp`
  (`RY15 = 9798`, `GY15 = 19235`, `BY15 = 3735`) with `CV_DESCALE` (round).

All three sets sum to 32768, so an already-grey source (`R = G = B`) round-trips exactly under
every formula — grayscale inputs never shift.

`ImageFiles.FormulaFor(ImageSharp format name)` picks the set: `PNG → Png`,
`BMP/TIFF → BmpTiff`, anything else → `Cvt`.

## Decoding

- ImageSharp `Image.Load<Rgba32>` decodes every frame (multi-page TIFF), then
  `AutoOrient()` mirrors OpenCV's default EXIF handling.
- Alpha is ignored, matching OpenCV's gray output.
- The decoder buffers non-seekable streams because `Image.DetectFormat` needs seeking.

## Known limitation

Colour **JPEG** cannot be bit-exact: OpenCV decodes with libjpeg(-turbo) and does the
YCbCr→grey step there, whereas ImageSharp has its own decoder. Colour JPEGs therefore fall
back to the `Cvt` coefficients and may differ by ±1. PNG/BMP/TIFF — the formats the pipeline
actually reads — are exact.
